# ExcaliWorks 사업 정의

상태: 고객·해결 목적은 사용자 확인 / 기술구조는 기존 논의 기준선 복원 / 구현 전
갱신일: 2026-10-22

## 고객과 문제
주요 고객은 금융회사와 기업의 IT 담당자다. 기업 내 IT·업무 지식이 산재하고 담당자마다 따로 관리되어, 최신 아키텍처와 설계 이유를 함께 이해하고 변경·취약점 영향을 파악하기 어렵다.

## 제공 가치
**흩어진 IT·업무 지식을 아키텍처 중심으로 연결하고, 자산·관계·설계 근거를 함께 탐색하는 환경을 구축한다.**

- Excalidraw 기반 ArchMap에서 전체 구조와 상세 구조를 줌인·줌아웃하며 탐색한다.
- CMDB와 연계해 아키텍처 자산을 식별하고 변경 이력을 관리한다.
- SBOM·CVE 정보와 내부 자산을 연결해 취약점 영향 대상과 맥락을 찾는다.
- 설계문서·ADR·운영절차를 연결해 담당자 변경 시에도 지식과 결정 이유를 전달한다.

## 핵심 유스케이스
| 구분 | 해결할 질문 |
|---|---|
| Vulnerability Navigator | 이 CVE 관련 대상은 어디에 있고 어떤 시스템과 연결되는가? |
| Architecture Change | 변경 시 함께 검토할 의존관계와 설계 근거는 무엇인가? |
| Knowledge Transfer | 이 시스템은 왜 이렇게 설계됐고 누가 관리하는가? |

공통 사용자 흐름: **Search → Locate → Zoom → Inspect**.

## 사업화 방향과 미확정 사항
기존 논의는 금융 IT 경험, 방법론, Adapter·Mapping·템플릿을 결합하는 구축·제품 사업을 지향한다. 고객 도입을 수작업 데이터 입력에서 재사용 가능한 연계·모델링으로 옮기는 것이 경쟁력 가설이다.

유료 POC, 초기 구축·연계, 연간 라이선스·유지보수, 확장 모듈·교육은 수익모델 후보다. 가격·계약·최초 판매 상품·매출 목표·일정·고객 확보는 미확정이다. 금융사 레퍼런스는 앞으로 축적할 목표이며 확보 실적이 아니다.

기술 기준은 [ARCHITECTURE.md](ARCHITECTURE.md), 확장안은 [OPTIONS.md](OPTIONS.md), 결정 상태는 [결정 기록](../03_decisions/DEC-001-architecture-baseline.md)을 참조한다.

## 고객 사용 환경과 현재 요구

Obsidian·Excalidraw를 중심으로 기업의 아키텍처 지식 관리 환경을 구성한다. 별도 웹사이트 상품은 만들지 않는다. 줌 탐색과 장비 선택 시 정보 팝업을 제공하는 방향은 [DEC-004](../03_decisions/DEC-004-obsidian-navigation-and-device-popup.md)에 기록한다. 구체 팝업 동작은 미검증이다.

사용자 회사의 PowerPoint 구성도·Excel 자산목록 분리, 공유·발견·교육·보고·갱신 문제와 UX 제안은 [탐색 UX](NAVIGATION-UX.md)를 참조한다. 최초 유료 유스케이스·우선순위는 미확정이다.

# PowerPoint → SVG 기반 ArcMAP 탐색 아이디어

> 후속 결정: 2026-10-21 사용자 PDF 선명도 확인 후 출력 형식을 PDF로 전환했다. 현재 기준은 [PDF 탐색 방식](PDF-MAP-EXPLORATION.md)과 [DEC-003](../03_decisions/DEC-003-pdf-map-exploration.md)이다. 아래는 이전 SVG 아이디어를 보존한 기록이다.

- 기록일: 2026-10-21 (한국 시간)
- 상태: 사용자가 제시하고 저장을 요청한 아이디어. 구현·성능 검증 전이며 제품 전체 설계의 확정을 뜻하지 않는다.
- 근거: 현재 대화에서 사용자가 과거 논의 내용을 직접 복원했다. 과거 SVG 논의 원문은 확인하지 못했으며 이 문서는 이번 설명을 기준으로 한다.

## 사용자 제안 원형

1. PowerPoint에서 슬라이드 캔버스를 가능한 한 크게 설정한다.
2. 전체 네트워크 구성도를 최대한 상세히 작성한다.
3. 슬라이드를 고화질 SVG 이미지로 내보낸다.
4. SVG 파일을 Obsidian의 Excalidraw에서 불러온다.
5. 이미지의 기본 확대·축소를 이용해 지도처럼 전체 구조와 상세를 탐색한다.
6. 특정 Zone이나 영역의 추가 상세가 필요하면 파일 연결과 Excalidraw 플러그인의 프레임 방식 등을 활용해 이동한다.

PowerPoint가 구성도 작성·수정 원본이고, Excalidraw는 SVG 탐색과 상세 자료 연결의 화면이라는 구상이다. 서버 아이콘만 SVG로 바꾸는 방식이나, 모든 구성도를 별도 화면으로 나누어 이동하는 방식으로 해석하지 않는다.

## 기대하는 사용자 경험

- 전체 보기: 주요 네트워크 영역과 연결을 파악한다.
- 확대: 같은 이미지 안에서 DMZ·내부망·서버군의 위치 맥락을 유지하며 세부 내용을 읽는다.
- 근접 확대: 원본에 그려둔 장비명·연결 설명을 확인한다.
- 추가 상세: 현재 이미지보다 상세한 Zone·클러스터 구성은 연결 파일이나 프레임을 통해 확인한다.
- 문서 연결: 설계 근거·운영절차 등은 관련 문서로 확인한다.

한 이미지 안의 확대는 원본에 이미 담긴 상세를 읽는 것이다. 확대에 따라 새로운 객체를 동적으로 생성하거나 로딩하는 의미적 줌의 구현을 전제하지 않는다. 프레임·파일 이동의 구체 동작과 원래 위치 복귀 경험은 검증 대상이다.

## 배경과 기대 효과

- 사용자는 여러 드로잉을 계속 넘기기보다 지도처럼 줌인·줌아웃하는 경험을 선호한다고 설명했다.
- 앞서 논의한 드로잉당 약 1,000개 객체 제한은 성능 회피 가설이었다. SVG 방식 복원 후의 확정 상한으로 취급하지 않는다.
- 상세한 원본을 이미지로 활용하면 Excalidraw에서 원본의 모든 도형을 개별 편집 요소로 관리하는 부담을 줄일 수 있다는 기대가 있다. 실제 성능 개선은 미검증이다.
- 기존 작성 도구와 탐색 도구를 활용해 초기 개발 범위를 줄일 수 있다는 것은 AI의 평가이며 실증 결과가 아니다.

## AI 검토 의견과 주의할 설계 지점

- 캔버스 크기뿐 아니라 큰 영역명·Zone명·장비명의 글자 크기와 시각적 위계를 설계해야 전체와 상세를 모두 읽기 쉽다.
- SVG가 하나의 이미지로 배치되어도 내부 복잡도와 용량에 따른 렌더링 부담이 사라진다고 보장할 수 없다.
- 이미지 안의 더 상세한 내용과 별도 자료로 넘어가야 하는 영역을 사용자에게 구분해 보여줄 필요가 있다.
- PowerPoint 수정 후 SVG를 교체할 때 링크·프레임의 위치가 어긋날 수 있다. 이미지 크기·배치 유지와 연결 영역 재확인 절차를 검토한다.
- 원본 수정일과 이미지 반영일, 원본·SVG·연결 자료의 대응을 관리할 필요가 있다.
- 이 구상 자체만으로 개별 자산 식별·검색·CVE 강조·관계 분석이 자동 제공되지는 않는다. 해당 기능에는 자산과 이미지 위치의 매핑 등 추가 설계가 필요하다.

## 제안된 검증 순서 — 아직 실행하지 않음

1. 현실적인 시스템의 상세 네트워크 구성도 한 장을 PowerPoint로 작성한다.
2. SVG 내보내기와 Excalidraw 불러오기의 호환성, 텍스트·선·글꼴·확대 선명도를 확인한다. PowerPoint의 실제 캔버스·내보내기 제약도 확인한다.
3. 대상 Obsidian·Excalidraw 버전과 장비에서 열기·이동·확대·축소·저장/재열기를 측정한다.
4. Zone 한 곳에 파일 연결·프레임 방식을 적용해 상세 이동과 원래 맥락 복귀를 확인한다.
5. PowerPoint 원본을 수정하고 SVG를 교체해 연결 영역의 정합성과 갱신 부담을 확인한다.
6. 결과를 토대로 한 장의 적정 범위·이미지 복잡도·분할 기준을 정한다. 1,000개나 특정 용량을 검증된 안전선으로 미리 확정하지 않는다.

## 기존 기준선과의 관계

이 문서는 [기술구조 기준선](ARCHITECTURE.md)의 시각 표현·탐색 방식을 구체화하는 후보다. Entity/Registry, Draft/Publish 및 원천 데이터 책임을 폐기하거나 변경하는 결정은 아니다. [확장안](OPTIONS.md)의 AI Drawing과도 구분하며, 우선 정적 SVG 기반 탐색의 유용성을 확인하려는 아이디어다.

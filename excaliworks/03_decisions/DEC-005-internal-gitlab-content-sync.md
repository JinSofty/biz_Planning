# DEC-005: 사내 GitLab 기반 콘텐츠 공유와 담당자 중심 운영

- 상태: 확정 (운영 방향). 실제 배포·자동화·충돌 복구 검증 전.
- 날짜: 2026-10-22 (한국 시간)
- 확정 근거: 사용자가 보안자료는 GitHub를 사용할 수 없으므로 사내 GitLab을 설치해 Git 방식으로 콘텐츠를 관리하자고 명시했다. 담당 분야별 직원이 자기 아키텍처를 관리하고 타인 수정도 Git 이력으로 추적·복구하는 운영안을 제시했다. 최소 운영 규칙에 대한 평가 후 “지금 논의한사항을 확정해서 커밋하고 깃허브에 올려”라고 요청했다.
- 결정 내용:
  1. 고객사 보안 ArcMap 콘텐츠는 사내 설치 GitLab에서 Git 방식으로 공유·버전 관리한다. 해당 보안 콘텐츠는 GitHub에 올리지 않는다.
  2. 직원은 각 PC의 Obsidian·Excalidraw에서 작업한다. 구성도·설명 및 자산 메타데이터 노트·PDF/SVG 첨부자료·Dataview 조회 노트를 공유 대상으로 삼는다.
  3. 네트워크·시스템·보안·응용 등 각 담당자가 자기 영역을 유지관리한다. 구성도 파일별 관리 담당자를 표시한다.
  4. 초기에는 담당자가 공통 브랜치에 직접 반영할 수 있다. 모든 수정에 검토 요청·사전 승인을 의무화하거나 편집 잠금·별도 승인본 배포 체계를 기본 요건으로 두지 않는다.
  5. 수정 전에 최신 변경을 받고, 작업 후 관련 파일만 변경 이유와 함께 묶어 전송한다.
  6. 타인 콘텐츠를 수정한 경우 이유를 남기고 담당자에게 알린다. 일률적인 사전 승인 의무는 두지 않는다.
  7. 공통 브랜치의 강제 덮어쓰기를 금지한다. 잘못 반영된 변경은 기존 이력을 보존하는 취소 커밋으로 복구한다.
  8. 충돌 시 자동으로 한쪽을 덮어쓰지 않고 양쪽 수정본을 보존한다. Excalidraw 파일은 임의 텍스트 병합으로 그림의 정합성이 보장된다고 가정하지 않는다.
  9. 열람 가능한 범위가 다른 자료는 저장소를 분리한다. 같은 저장소의 폴더 숨김을 보안 경계로 사용하지 않는다.
- 검토한 대안: Obsidian Sync, 전면적인 승인 후 배포, 편집 잠금·일괄 검토 의무화. 초기에는 담당 책임과 Git 이력 중심의 간단한 운영을 선택하고 필요 시 통제를 추가한다.
- 이유와 근거 자료: 불특정 다수 공동 편집이 아니라 담당 영역이 분리된 사내 전문가 사용을 전제로 한다. 충돌 가능성을 과도하게 가정해 초기 사용성을 떨어뜨리지 않되, 추적·복구 및 실제 충돌 보존은 확보한다.
- 예상 영향: Obsidian 안에서 최신본 받기 → 수정 → 변경 확인 → 전송을 간편하게 제공하는 흐름에 집중한다. UI·도구·자동 실행 주기는 후속 설계다.
- 재검토 조건: 동일 파일 동시 수정·공통 자산 수정 충돌이 빈번하거나, 복구 부담·보안 권한·감사 요구가 현재 규칙으로 해결되지 않는 경우. 필요 영역에만 검토·잠금을 추가한다.
- 이전/후속 결정: DEC-001 및 ARCHITECTURE.md에서 GitLab을 운용 제안으로 두었던 부분을 이번 고객사 콘텐츠 운영 방향으로 구체화한다. Registry·원천 연계·Semantic Publish 기준선은 유지한다.
- 함께 갱신할 문서: ARCHITECTURE.md, STATUS.md, README.md.

## 역할과 경계

- 사업 기획 기록용 JinSofty/biz_Planning GitHub 저장소와 고객사 보안 콘텐츠용 사내 GitLab은 별개다. 이번 요청은 사업 기획 결정 문서를 GitHub에 전송하는 승인이다. 실제 보안 구성도·자산 데이터는 포함하지 않는다.
- Git 파일 전송/병합과 Architecture Publish는 서로 다른 사건이다. Git에서 파일을 되돌려도 Registry DB가 자동으로 복구되지는 않는다.
- 여러 그림에서 공유하는 장비 메타데이터는 중복 작성하지 않고 항목별 관리 책임을 정한다. 노트·Registry·Excel/CMDB의 필드별 원본과 동기화 정책은 아직 미확정이다.
- 전체 네트워크도 등 여러 분야가 함께 수정하는 파일은 관리자를 정하거나 변경 전 협의한다.
- 개인 작업 화면·개인 메모는 공통 콘텐츠와 구분한다. 플러그인·설정 배포 범위는 미확정이다.

## 남은 설계·검증

- GitLab 설치·저장소 구분·계정/권한, 브랜치명, 대용량 첨부 처리와 백업 방식.
- Obsidian의 받기/전송 UI와 수동·자동 실행 주기. 개인별 Git 작성자 및 인증 설정.
- Excalidraw 충돌 발견·수정본 보존·취소 커밋 복구의 실제 시험.
- 파일 revision과 Registry Publish revision 연결·DB 복구 정책.

# POC-001: 라이브러리 웹서버의 DMZ 배치

기록일: 2026-10-21 / 결과: 실제 Obsidian Drawing 생성 성공(사용자 확인)

## 목적과 환경
- ArcMap의 요소기술 중 사전 등록한 라이브러리 객체를 자동 배치할 수 있는지 검증.
- Obsidian Excalidraw 플러그인 2.29.0.
- Vault 내부 라이브러리 경로: `Excalidraw/Libraries/local-library.excalidrawlib`.
- 사용 항목: 첫 번째 Web 객체, ID `L-5apBcsCZmLyXEcM2c_h`.
- 원본은 rectangle·line·text 17개 요소이며 roughness=0. 래스터 이미지가 아님.
- 이번 저장소에는 라이브러리 전체와 고객 Vault 자료를 복사하지 않음. 스크립트 실행에는 원래 라이브러리 파일이 필요함.

## 구현
선택한 회전하지 않은 DMZ 사각형 내부에 Web 심볼을 복제하고 `web_007`, `10.0.0.250` 라벨을 추가한다. 원본 seed·스타일을 보존하고 요소 ID·그룹 ID·내부 참조를 재매핑한다. 복제본과 라벨을 그룹화하고 Draft 테스트 메타데이터를 남긴다.

사각형 크기 부족·배치 위치 충돌·동일 테스트 서버 중복·선택 누락 시 중단한다. 대상 Zone은 이름으로 검색하지 않고 사용자가 선택한다. 자동 줌은 없으며 배치 후 선택된 요소를 Shift+2로 확대할 수 있다.

## 진행 과정과 수정
1. 라이브러리 파일 및 설치된 플러그인·스크립트 폴더 설정을 확인했다.
2. 첫 파일은 YAML·설명문·Markdown 코드 상자를 함께 포함했다.
3. 명령 목록에는 등록됐으나 선택해도 Drawing이 생성되지 않았다.
4. 설치된 2.29.0 실행기에서 YAML만 제거하고 나머지 본문 전체를 JavaScript로 컴파일하는 것을 확인했다.
5. 설명문·코드 상자를 제거해 YAML 아래에 실행 코드만 남긴 후 같은 파일을 교체했다.
6. 사용자가 ‘제대로 그림이 생성되었어’라고 확인했다.

실행 경로: 테스트 Drawing에서 DMZ 테두리 선택 → Cmd+P → ArcMap 검색 → `Excalidraw: (Script) ArcMap-Place-WebServer` 실행.
앞서 안내한 하단 팔레트 모양 버튼은 화면에서 Duplicate 버튼으로 확인되어, 명령 팔레트 방식으로 안내를 수정했다.

## 증거와 검증 범위
| 항목 | 결과 |
|---|---|
| 실제 Obsidian Drawing 생성 | 사용자 성공 확인 |
| 실행 형식 | 설치된 Script Engine의 컴파일 방식 대조, 수정 파일 전체 컴파일 및 모의 실행 |
| 복제 요소 수·ID/그룹 재매핑·배치 경계·seed/roughness 보존 | 실제 라이브러리를 입력으로 한 모의 검증 통과 |
| 크기 부족·중복·충돌·미선택 | 모의 검증 통과 |
| 저장 후 다시 열기·실행 취소·그룹 이동 | 사용자 확인 미완료 |
| 손그림 스타일 만족도 | 미측정. 이번에는 roughness 0 원본을 그대로 복제 |
| 줌 탐색 UX·대규모 성능·명령 해석 정확도 | 미검증 |

성공은 객체 자동 배치의 첫 기술적 가능성을 확인한 것이다. AI 자동화·제품 성능·고객 만족도를 입증한 결과로 확대 해석하지 않는다.

## 아직 연결하지 않은 기능
로컬 Qwen, 자연어 명령, 자동 DMZ 식별, 업무·조직·담당자 연결, CMDB/Registry/Publish, 빈 공간 자동 탐색·다중 서버 배치, Zone 이동 시 자식 추종, 자동 줌.

## 다음 검증 순서 제안
1. 저장/재열기·실행 취소·그룹 이동과 시각 스타일을 확인.
2. Search → Locate → Zoom → Inspect 탐색 흐름과 계층 이동 비교.
3. 같은 배치 실행기를 구조화 명령으로 호출하도록 분리.
4. 로컬 Qwen 명령 추출을 연결하고 모호한 대상·중복·누락을 평가.

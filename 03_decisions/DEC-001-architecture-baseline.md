# DEC-001: 사업 목적과 기존 기술구조 기준선 복원

- 날짜: 2026-10-21
- 상태: 사업 목적은 사용자 확인 / 기술구조는 기존 논의 기준선으로 복원 / 확장안·세부안은 미확정
- 근거: 현재 채팅의 고객·목적 설명 및 ‘다른 채팅방에서 논의하고 주요 기술구조를 확정한 내용을 정리해서 커밋’ 요청. 과거 요약의 유지 방향과 조회 가능한 수정 논의를 대조했다.

## 기록 내용
1. 금융회사·기업 IT 담당자의 산재한 지식 관리, 시각적 아키텍처 탐색, CMDB 연계, 변경 관리와 CVE 영향 탐색을 사업 목적으로 기록한다.
2. Excalidraw/ArchMap, Obsidian, PostgreSQL Architecture Registry, CMDB·SBOM·CVE 연계를 기술구조 기준선으로 복원한다.
3. 일반 시각 요소와 Managed 요소, Draft와 Publish를 분리한다.
4. Publish는 명시되거나 수집된 의미정보를 검증·동기화한다. 일반 선에서 의미를 추측해 확정하는 초기 구상은 채택하지 않는다.
5. 모호한 항목은 Review Queue에서 처리하고 Imported/Explicit/Inferred 및 승인 상태를 추적한다.

## 상태 판단의 한계
원문 조회는 일부 최근 턴만 제공했다. 과거 정리 역시 모든 제안이 사용자 최종 승인을 받은 것은 아니라고 명시한다. 따라서 본 기록은 복원된 기준선이며 개별 상세 설계 전부의 승인 증명이 아니다. SQL 스키마·가격·일정·Architecture OS·AI Drawing·GitLab 의무 사용은 확정으로 기록하지 않는다.

## 검토한 대안과 이유
- 모든 선을 자동 의미화: 의미가 복수로 해석되어 잘못된 관계가 공식화될 수 있음.
- 모든 도형을 Registry에 등록: 설명용 그림까지 관리 부담이 생김.
- 의미관계를 파일과 원천별로 중복 관리: 정체성·탐색·변경 추적이 어려워 연결 Registry를 둠.

## 영향과 재검토
상세 설계와 첫 POC의 출발점으로 사용한다. 새로운 원문·사용자 정정·실데이터 검증으로 변경되면 후속 결정 기록을 추가한다.

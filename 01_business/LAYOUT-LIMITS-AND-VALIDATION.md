# 객체 자동 배치의 한계와 검증안

상태: 사용자 문제 제기와 코드 확인을 바탕으로 한 제안. 제품 방향으로 확정하지 않았으며 구현 변경 없음.

## 현재 코드의 기준
- 대상: 사용자가 선택한 회전 없는 사각형.
- 크기: 인식된 서버 그룹의 몸통 너비 중앙값을 적용. 다른 형태의 서버도 너비 기준이며 시각적 무게나 장비 역할은 반영하지 않음.
- 공간: 좌우·아래 여백은 32와 존 가로/세로의 5% 중 최솟값, 위쪽 예약은 72와 존 높이의 18% 중 최솟값.
- 위치: 좌측/가운데 및 기존 요소 경계 주변 후보를 생성한 뒤 y, x 오름차순으로 첫 비충돌 위치를 선택. 중앙 우선이나 사용자 의도 기반 배치가 아님.
- 부족 시: 초기 맞춤 배율에서 10%씩 더 축소하며 최대 100회 탐색. 최소 글자 크기 제한이 없어 지나치게 작아질 수 있음.
- 충돌: 요소별 축 정렬 경계 상자로 판정. 연결선·회전·복잡한 그룹의 실제 시각적 공간과 다를 수 있음.
- 미지원: 업무 흐름, 계층, 순서, 연결선 경로, 정렬선/간격, 사용자 수동 의도, Zone 자동 확장.

## 핵심 한계
빈 공간과 의미상 올바른 위치는 다르다. Zone 소속만으로는 순서나 이웃·계층을 추론할 수 없다. 기존 서버와 폭을 맞춰도 높이/라벨/역할이 다르면 시각적으로 동일하게 보이지 않는다. 무제한 축소는 가독성을 해친다. 객체 추가만 빠르게 해도 사후 수작업 보정이 늘면 총 작업시간은 줄지 않는다.

## 제안: 단계별 자동화
1. 기본은 기준 객체를 선택한 상대 배치: 선택 서버와 같은 표시 크기, 오른쪽/아래, 동일 간격, 같은 정렬선. 기존 객체는 고정.
2. 신규 Zone은 템플릿 선택: 가로 흐름, 세로 계층, 격자, 수동 배치. 데이터 순서/명시한 관계를 사용하고 좌표만으로 업무 순서를 확정하지 않음.
3. 공간 부족 시 정책: 가독성 하한 이내 축소 → 줄바꿈 또는 사용자 선택에 따른 Zone 확장/부분 재배치. 존 확장은 주변 존과 충돌 및 연결선 변경까지 미리보기로 보여줌.
4. 연결 기반 레이아웃은 후속: 방향·종류·소속 등 구조화된 관계를 입력으로 후보 생성. AI는 의도 해석, 좌표 계산은 제약 기반 실행기가 담당. 의미가 부족하면 기준 객체나 위치 지정을 받음.
5. 광범위 변경은 후보 미리보기 → 사용자 선택 → 일괄 적용/실행 취소. 잠금·고정 위치 보호.

## 표현과 구조
- 자산: 안정적인 ID, 편집 가능한 이름, 종류, 업무/연결 관계.
- 표현: 심볼, 표시 크기, 좌표, 정렬/간격, 수동 고정 여부.
- Zone 배치 정책: 방향, 배치 순서, 여백, 크기 기준, 최소 가독성, 공간 부족 처리.
이는 구현 제안이며 현재 메타데이터에 전부 존재하지 않는다.

## 다음 실험 제안
- 먼저 상대 배치 한 가지로 검증: 기존 서버 선택 → 오른쪽에 같은 크기/간격 → 공간 부족 시 미리보기와 대안.
- 동일한 작업을 라이브러리 수동 배치와 비교. 빈 존, 정렬된 존, 혼잡한 존, 연결선이 있는 존에 각각 적용.
- 측정: 명령부터 최종 수동 보정 완료까지 시간, 보정 횟수, 의도한 순서/정렬 유지, 읽기 어려운 라벨, 예상 밖 기존 객체 이동.
- 제안 통과 기준: 기존 객체의 예상 밖 변경 0건, 가독성 하한 위반 0건, 단순 추가 작업에서 총시간이 수동 방식보다 감소. 수치 목표는 사용자와 후속 확정.
- 감소 효과가 없으면 독립 자동 배치 기능의 우선순위를 낮추고 자산/관계 일괄 갱신과 탐색의 보조 수단으로 재평가.

코드 개선은 아직 적용하지 않았고 현재 자동 축소 동작을 유지한다. 서버명 동기화는 별도 개발 요구사항으로 구현했으며, 후속 사용자 요청에 따라 코드와 함께 개발 브랜치에 기록·전송한다. 이 문서의 개선 제안 확정을 뜻하지 않는다.
